设计规范怎样改变了测评 Lab？

选择一个页面，查看同一任务的两种布局。左侧是旧版窗口，右侧是新版实机。两边都保留 Lab 侧栏，可以点击放大，直接比较同一操作在窗口中的位置。

怎样知道下一步该做什么？

第一次打开测评页，音频、工作簿和模型都尚未选择。

页首给出一个主操作

旧版把 Start Run 放在第三组，下方还有尚不可用的暂停、继续和取消。新版把 Start run 放到标题旁，未配好时写明先选择音频文件夹。

配置就绪后，同一个位置显示本次要跑的录音数。开始后，进度和控制会滚入视野。

怎样确认按钮会操作哪个模型？

两版都从已安装的 Parakeet 开始，随后是 Silero 和 Qwen。Parakeet 的模型大小同为 483.1 MB，磁盘占用同为 483.3 MB。比较同一行里的状态和操作即可。

列表按操作对象分组

旧版已经分别列出 Model size 和 On disk。全库删除在页首，单项删除在每行右端。新版保留这两个容量读数，把单项操作并排放在型号下，把全库删除收进 Advanced model tools。

辅助功能中的下载按钮也读得出具体型号。在窄窗中，状态和操作可以分行排列。

哪个资源包正在影响测评？

两边使用同一个导入包，标识均以 b2fca462 开头，创建时间均为 11 月 21 日上午 6:11。可以直接对照当前包、导入按钮和已导入列表的位置。

区分页面操作和条目操作

旧版把一个导入按钮放在当前包与已导入列表之间。新版把 Import resource pack 提到页首，第一张卡直接回答当前在用哪个版本。

这个包在新版列表中同时标出 Imported 和 In use，来源和当前使用状态可以一起核对。

怎样从一条历史记录继续操作？

两版都是同一批七条 UI Tiny Qwen 08 记录，各完成一条录音、零条失败。对照最新一条，看时间、状态和打开结果的入口。

让状态和下一步操作相邻

旧版把记录排成六列，开始时间在当前宽度下被截断。新版以运行名称为标题，完整显示时间，把录音数、完成数、失败数和 Open Results 放在同一组内。

取舍也能从图中看出。新版一条记录占用更多纵向空间。旧表格更紧凑，便于横向对齐数字。

把设计要求变成可以检查的行为

三个文件按钮，各有名字

此前测试环境中的旧版内容区，三个文件选择按钮在 macOS 辅助功能树中都叫 Choose…。新版分别标识音频文件夹、工作簿和输出文件夹。宽窗和 360 pt 窄窗均已核对名称和启用状态。

启动后看得见进度

在 640 × 680 pt 窗口放入 24 条录音和 8 条提示。触发开始后，新版自动回到进度和控制所在的位置。后续进度更新不会反复把用户拉回页首。

第二次打开也能回到结果

打开一条历史结果，滚回列表，再打开同一条。独立验证中，两次都回到结果区，汇总只读取一次。布局审查也检查了这样的重复操作。

四张旧图由使用者提供。四张新图来自正在运行的 macOS 测试构建 1.10.17（34d630c4）。从同一 2160 × 1480 像素窗口截取 Lab 区域，保留侧栏，统一取景为 1704 × 1448 像素。旧图宽 1684–1722 像素、高 1446–1462 像素。设计规范为页标题、主次按钮、组间距、卡片和语义色提供依据。启动后滚动与重复打开结果属于本次实现中验证的交互。此案例未测量用户完成任务所需的时间。
